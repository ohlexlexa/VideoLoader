# DownMax (до 2.0 — «Загрузка видео») — заметки для работы

Устройство и установка — в README.md. Код приложения — `Sources/`, скрипты иконки — `scripts/`. Здесь то, что не видно из кода: решения, подводные
камни и порядок проверки.

## Как работать

- Отвечать пользователю по-русски. В разборах задавать по одному вопросу за сообщение.
- Не коммитить и не пушить без явной просьбы.
- Перед пересборкой проверить, не идёт ли загрузка у пользователя:
  `pgrep -f "yt-dlp|h264_videotoolbox"`. `build.sh` удаляет и заново ставит
  `/Applications/DownMax.app`, поэтому приложение надо закрыть
  (`osascript -e 'tell application id "local.ohlexlexa.downmax" to quit'`).
- После изменений в `chrome-extension/`: пересобрать приложение (расширение вшито
  в бандл), запустить его (при запуске оно копирует расширение в
  `~/Library/Application Support/DownMax/chrome-extension`) и попросить пользователя
  нажать ↻ у расширения в Chrome и обновить вкладку. Safari берёт расширение из бандла, но кэширует
  его по версии: поднимать `version` в `manifest.json`. Нажимать в Safari computer-use не может
  (только смотреть), проверку там делает пользователь.
- Тестовые файлы в `~/Downloads` после проверки удалять. Свои файлы пользователя не трогать.

## Как проверять

- Приложение: отправить ссылку `open -g "downmax://download?url=…&title=…"` и смотреть
  на `~/Downloads`, `~/Library/Caches/DownMax`, `~/Library/Logs/DownMax.log`.
  Окно смотреть через computer-use (bundle id `local.ohlexlexa.downmax`).
- Короткий тестовый ролик: `https://www.youtube.com/watch?v=jNQXAC9IVRw` (`&quality=144`).
- Повтор той же ссылки в течение 10 минут приложение не качает, а спрашивает. Для тестов
  менять `title`.
- Расширение во встроенный браузер не ставится. Логику проверять, вставляя функции
  из `popup.js` на настоящую страницу через javascript_tool или прогоняя их в Node
  (`fetchText`, `vimeoVideo` и т.п.). Вид окошка — на стенде с заглушками `chrome.*`,
  поднятом через `python3 -m http.server` (file:// в браузерной панели статичен).
- Тестовые страницы: GetCourse — `https://formfactor.getcourse.ru/materials` (4 плеера,
  без входа); Threads — `@designabdullin/post/DdrVN0II3To` (без звука),
  `@inconst8/post/DdqWJ4ojaPR` (со звуком); Instagram reel `DdrUVLCtj87`, карусель
  `DdnuuABjzns`; Vimeo — `https://vimeo.com/1041249831/6f94f564a8`; VK — ролик
  `https://vkvideo.ru/video-220754053_456246684` (до 1080p, 2 часа — для загрузки не брать),
  клип `https://vkvideo.ru/clip-232619944_456247484` (короткий, для загрузки).

## Решения, которые не надо переделывать

- **Окно создаёт AppDelegate (NSWindow + NSHostingController), а не SwiftUI-сцена.** При запуске
  в фоне (браузером по ссылке) SwiftUI окно не открывал, а открыть его из кода нельзя. Загрузки
  живут в `DownloadManager.shared` и от окна не зависят.
- **Ссылки `downmax://` (и старые `videoloader://`) принимает свой обработчик Apple Event (`kAEGetURL`)**, а не
  SwiftUI: каждая ссылка приходит ровно один раз, и виден отправитель для журнала.
- **Защита от дублей:** одинаковая ссылка в течение 5 секунд отбрасывается, в течение
  10 минут приложение спрашивает. Одинаковые загрузки параллельно не запускаются: они писали
  в одни и те же файлы и портили результат.
- **«+» в параметрах ссылки — это пробел** (так кодирует `URLSearchParams`), настоящий «+» приходит как `%2B`.
- **Пауза и продолжение — как у торрентов (с 2.0, решение пользователя).** У каждой загрузки видео своя
  папка `~/Library/Caches/DownMax/<uuid>`; она живёт, пока загрузка в списке и не завершена (в том числе
  на паузе и между запусками), и удаляется при завершении, отмене или удалении из списка — место занимает
  только то, что видно в списке. Список — `Application Support/DownMax/downloads.json`. Выход ничего
  не спрашивает: идущие загрузки останавливаются и продолжаются при запуске, перекодирование начинается
  заново. Пауза только во время скачивания (не на склейке/перекодировании); карусели после паузы
  качаются заново. При запуске и выходе приложение чистит в `~/Library/Caches/DownMax` всё остальное,
  поэтому свои временные файлы туда класть нельзя.
- **Иконка.** macOS 26 в тёмном режиме затемняет иконки из .icns. Поэтому: 1) после подписи
  ставится «своя» иконка бандла (`set_icon.swift`, и приложение повторяет это при запуске);
  2) плитку Дока всегда рисует приложение (`DockProgress`), без загрузок — просто
  иконка. Из-за «своей» иконки `codesign --verify --strict` ругается на «detritus»
  (обновлятор проверяет подпись без `--strict` и в распакованном архиве, где «своей» иконки нет).
- **Любое видео должно открываться в QuickTime.** Формат выбирается так: лучшее разрешение,
  а среди равных H.264 и AAC (до 1080p YouTube почти всегда отдаёт H.264). Если после загрузки
  видео в VP9/AV1 (4K YouTube, Instagram) или звук в Opus/Vorbis, файл перекодируется
  `h264_videotoolbox` + AAC, главы сохраняются, в окне виден прогресс. Пункт «Без
  перекодирования» в меню «Качество» (ключ `compatible`; в кнопке — «· H.264») сразу берёт H.264, даже если так ниже разрешение.
- **Имя файла** (2026-09-26, решение пользователя): кнопка «Имя: … ▾» в строке настроек: «Название» (по умолчанию),
  «Автор — Название», «Дата Название» (дата публикации) — ключ `nameStyle`, `NameStyle` в main.swift. Шаблоны yt-dlp
  `%(uploader,channel&{} — |)s` и `%(upload_date>%Y-%m-%d&{} |)s`: нет поля — без разделителя. Номер плейлиста — первым.
  Название от расширения с «@» (Instagram, Threads) — автор уже в нём, второй раз не ставится. Карусели, торренты и
  файлы по ссылке не затрагивает.
- **Субтитры** (2026-09-26, решение пользователя): пункт «Субтитры (русские и английские)» в меню «Качество» (ключ
  `subtitles`, выкл.; на кнопке «· Субтитры»). Только авторские `ru.*,en.*` (автоматические YouTube — без пунктуации и
  часто 429), дорожками mov_text внутрь mp4: `--sub-langs … --embed-subs --ignore-errors`. Без `--write-subs` — с ним
  рядом остаётся .vtt. `--ignore-errors` — не скачались субтитры, видео всё равно сохраняется. Перекодирование
  переносит их (`-map 0:s? -c:s copy`). Тестовый ролик с авторскими en: `dQw4w9WgXcQ` (у `jNQXAC9IVRw` только автоматические).
- **Главы YouTube** встраиваются в файл (`--embed-chapters`). В QuickTime на macOS 26 пункта
  «Вид → Показать главы» нет: главы — кнопка » на панели управления → «Главы».
- **Vimeo:** yt-dlp на vimeo.com требует входа в аккаунт, а через `player.vimeo.com/video/ID?h=ключ`
  работает без него. Переделку делает `vimeoPlayerURL()`.
- **GetCourse:** плееры — iframe `…/sign-player/?json=<base64>` с `video_hash`. Страница плеера
  отдаётся без Referer и содержит `previewUrl` и адрес `…/api/playlist/master/<hash>/…`
  (незашифрованный HLS). yt-dlp узнаёт его по содержимому.
- **Threads:** yt-dlp не поддерживает, берётся прямой mp4 (`video_versions`) из данных поста.
  Окошко показывает только посты, ссылки на которые есть на странице (в ленте — сначала те, что
  на экране): после переходов внутри Threads JSON в HTML остаётся от прежней страницы. Данные ленты
  ловит `instagram-bridge.js` (формат постов как у Instagram). Если поста из адреса нет — он
  загружается заново запросом со страницы (`threadsFetchPost`): из окошка Safari на threads.com
  не пускает, а без `Accept: text/html` Threads отдаёт страницу без данных поста.
- **Threads в приложении** (ссылка в поле, в т.ч. «Поделиться» `threads.com/share/…`): `ThreadsLink`
  открывает пост сам с `User-Agent: DownMax` и `Accept: text/html`. С «браузерным» User-Agent Threads
  отдаёт заготовку без данных и не переадресует share-ссылку на пост. Дальше — прямые mp4, как в окошке.
- **Карусели и фото Instagram:** yt-dlp фото не качает, приложение скачивает их само
  (`downmax://gallery`). Картинка — `image_versions2.candidates[0]` (исходник).
- **Лента Instagram:** данные приходят фоновыми запросами. `instagram-bridge.js` (world MAIN,
  document_start) перехватывает fetch и XHR и складывает посты в `window.__vlMedia`. Если вкладка
  была открыта до обновления расширения, её надо перезагрузить.

- **Safari — только в своей сборке пользователя.** appex собирается прямо в `build.sh` через `swiftc`
  (без Xcode-проекта), подпись — первым найденным сертификатом «Apple Development» (бесплатный аккаунт,
  только этот Mac). Без сертификата — ad-hoc и без Safari: ad-hoc расширение Safari отключает после
  перезапуска. Включить расширение программно нельзя, приложение только открывает настройки Safari.
  Сборка с Safari не обновляется из релизов (`Updater.enabled`): в релизе Safari нет, обновление бы его
  убрало; пользователь обновляет её пересборкой.
- **Релиз:** `NO_SAFARI=1 ./build.sh` (ad-hoc, без appex: личный сертификат на чужих Mac не работает
  и раскрывает почту из него), `ditto -c -k --keepParent build/DownMax.app DownMax-macOS.zip`, затем
  обычный `./build.sh`, чтобы вернуть пользователю сборку с Safari. Имя архива `DownMax-macOS.zip` и тег
  `vX.Y` обязательны: по ним обновлятор находит версию. Версию расширения (`manifest.json`) поднимать при
  каждой его правке — Safari кэширует расширение по ней.
- **Обновления** (`updater.swift`): раз в день и из меню. Состояние всегда видно в нижней строке справа (`UpdateBar`):
  «Версия · проверено сегодня в …  ↻ Проверить», «Доступна … Обновить · Что нового», «Обновлено до …» (сутки после
  обновления: `lastRunVersion` < текущей), «Не удалось проверить  ↻ Повторить», в сборке с Safari — «своя сборка».
  «Проверить» в строке отвечает в самой строке, без окон (`check(manual:inline:)`): крутилка не меньше 0,7 с, затем
  «✓ У вас последняя версия» на 4 с (просьба пользователя: иначе непонятно, сработало ли).
  «Что нового» — панель `WhatsNewView` над кнопкой (не GitHub: из приложения не уводим): описание релиза (`body`,
  markdown) до раздела «Установка…», кнопки «Позже» / «Обновить». Поэтому в описании релиза сначала — что нового
  простыми пунктами, инструкция по установке — ниже, под заголовком «Установка…». Релиз без DownMax-macOS.zip
  «Обновить» открывает страницу релиза в браузере. Проверить без релиза: собрать копию с
  другой версией (PlistBuddy + `codesign -s -`), отдать её и JSON как у GitHub через
  `python3 -m http.server` и указать `defaults write local.ohlexlexa.downmax updateFeed <адрес JSON>`;
  после проверки ключ удалить.
- **Окошко расширения:** прокручивается `main`, а не `body` — Safari подгоняет окошко
  под полную высоту body и обрезает без прокрутки.

- **VK:** yt-dlp качает открытые ролики vkvideo.ru и vk.com без входа. Ролик определяется
  по адресу (`video-1_2`, `clip-1_2`, `?z=video-1_2`), ссылки приводятся к `vkvideo.ru/video-1_2`
  (в расширении — `videoUrl()`/`vkVideo()`, в приложении — `vkVideoURL()`). Качества и превью —
  из встраиваемого плеера `vk.com/video_ext.php?oid=&id=` (ключи `mp4_<высота>`, `image`, страница
  в windows-1251); запрос делает background.js — у content script чужой домен закрыт CORS.
  Кнопка на странице ролика — за `[data-testid="video_page_share_button"]`, у клипов — в
  `roundedgroup` перед «⋯». Вид кнопок vk.com с входом в аккаунт не проверен.

- **Другие сайты — TikTok, Rutube, Дзен, X, Pinterest, Telegram, Twitch** (2026-09-26): качает сам yt-dlp, у нас —
  метки и фильтр (`Source.sites`), в окошке расширения карточка «Скачать видео / Звук» по адресу страницы
  (`SITES`/`otherSite()` в popup.js; Twitch — только клипы и записи, эфир бесконечен). На прочих страницах в пустом
  окошке — «Попробовать скачать со страницы». Одноклассники сейчас сломаны в самом yt-dlp (PR yt-dlp#17739) — добавить,
  когда починят. Reddit требует вход — ждёт куки. Тестовые ссылки (проверены): TikTok `@barudakhb_/video/6984138651336838402`,
  Rutube `video/3eac3b4561676c17df9132a9a1e62e3e`, Дзен `video/watch/6002240ff8b1af50bb2da5e3`, X
  `captainamerica/status/719944021058060289`, Pinterest `pin/664281013778109217`, Telegram `t.me/europa_press/613`,
  Twitch `clips.twitch.tv/FaintLightGullWholeWheat`.

- **Переименование в DownMax (2.0).** Старые ссылки `videoloader://` приложение принимает (расширения,
  поставленные раньше). При первом запуске `OldName.migrate()` переносит настройки из
  `local.ohlexlexa.videoloader` и удаляет старые кэш и журнал. Папку `Application Support/VideoLoader`
  не трогает: из неё браузер грузит старое расширение, пока его не поставят заново.

- **Торренты — aria2c** (`torrent.swift`), процесс на торрент, без RPC. В отличие от видео,
  торренты продолжаются после выхода и перезапуска: недокачанное лежит прямо в папке загрузки
  с `<имя>.aria2`, список — `Application Support/DownMax/torrents.json`. Раздача по умолчанию
  выключена (`--seed-time=0`); включённая (галочка при добавлении или ↑ «Раздавать» у готового) идёт до остановки
  (`--seed-ratio=0.0`). У готового торрента нет `.aria2` — aria2c запускается с `--check-integrity=true`, иначе
  начнёт качать заново. Отдано за запуск aria2c считается с нуля — сумма копится в `record.uploaded`. Невыбранные файлы aria2c создаёт «пустыми» (общие куски) — после
  загрузки приложение их удаляет. Файлов нет на диске — галочка в строке серая (у видео так же). aria2c внутри приложения.
- **Файлы по прямым ссылкам — тоже aria2c** (тот же `TorrentJob`, у записи есть `link`). Что это файл,
  решает `FileLink.detect` только для ссылок из поля ввода: запрос с `Range: bytes=0-0`, прерывается на
  заголовках; HTML, video/*, audio/*, m3u8 — в yt-dlp (прямой mp4 тоже: там перекодирование для QuickTime).
  Хранится исходный адрес, а не конечный: у GitHub конечный — временная подписанная ссылка.
  Ссылки из расширения всегда идут в yt-dlp. Тестовый файл: `https://proof.ovh.net/files/100Mb.dat`.

- **Ссылки с iPhone** (`remote.swift`): NWListener на порту 47863, по умолчанию выключен. Запрос
  `POST http://<LocalHostName>.local:47863/<ключ>` с JSON `{"url": …}` (или текстом со ссылкой). Ключ в
  адресе — единственная защита, поэтому умеет только поставить ссылку на скачивание (`LinkRouter.submit`,
  тот же путь, что поле ввода). Файл команды не генерируется: `shortcuts sign` требует входа в iCloud —
  пользователь собирает команду сам по инструкции в «Компонентах». Проверка без iPhone:
  `curl -X POST -d '{"url":"…"}' http://$(scutil --get LocalHostName).local:47863/<remoteKey>`.

- **Цвет бренда — розовый #FF4D80 (ступень 500)**, палитра в `ui.swift` (OKLCH, оттенок 8°):
  300 `#FEA5B5`, 400 `#FF7D99`, 500 `#FF4D80`, 600 `#E23A6D`, 700 `#BE2F5B`. Роли (инспекция по скиллу
  ui-color-system, 2026-09-26):
  заливки, выбор, галочки, прогресс, рамка фокуса — 500 в обеих темах, текст на них белый (Lc 63);
  ссылки мелким текстом — 600 светлая / 400 тёмная (`Color.brandLink`), наведение 700 / 300;
  наведение на заливке — темнеет в обеих темах (600); кольцо в строке меню — 600 на светлой строке;
  перекодирование — 500, как загрузка; ошибки — красный, не бренд (в окошке расширения `--error`
  `#C62A1E` / `#FF7A6E`). 500 мелким текстом не использовать: 3.2:1 на белом, Lc 40 на тёмном.
  `.tint(.brand)` — на каждый элемент, не на корень окна: на macOS 27 общий оттенок красит и обычные
  кнопки. Рамку фокуса поля ввода рисуем сами (1 px); выделение в меню macOS рисует сама.
- **«Оценить» и «Поддержать»** (`feedback.swift`) — кнопки внизу окна и пункты меню. Отзыв уходит письмом через
  Web3Forms (ключ в коде, письма автору, адрес в приложении не хранится; `replyto` — почта отправителя). curl
  Web3Forms режет Cloudflare-проверкой, URLSession проходит. К отзыву при 1–3★ (блок под текстом, перед почтой; при 4–5 его нет) прикладываются отмеченные галочками загрузки (у каждой ссылка, состояние, ошибка, параметры и строки журнала только про неё; при 1–3★ сама выбирается последняя неудачная), а не хвост журнала — он был длинным и непонятно про что:
  вложения у Web3Forms платные. Показываются всплывающей панелью (NSPopover) над своей кнопкой; из меню — сначала
  открывается окно. Щелчок мимо не закрывает панель, пока в отзыве есть текст. Размер панели задаёт содержимое через
  `onGeometryChange`: `sizingOptions = .preferredContentSize` на форме со звёздами и TextEditor зацикливал
  раскладку и ронял приложение. В фоновом режиме computer-use панель сразу закрывается (приложение не активно).
  «Поддержать» внизу окна (`DonateButton`) — стиль `.brandLink`: и слово розовое, не только сердце (просьба пользователя). Сердце всегда залитое розовое («живое сердце не пустое», решение пользователя) и бьётся всегда — слоем Core Animation (`HeartIcon`): бесконечная

## Подводные камни

- YouTube запрещает `innerHTML` (Trusted Types): DOM собирать через `createElement`.
- Ряд кнопок YouTube (`ytd-menu-renderer`) обрезает всё по вертикали (`overflow: hidden`),
  поэтому меню у «Скачать ▾» лежит в `<body>` с `position: fixed`.
- Переменные цветов YouTube (`--yt-spec-*`) больше не заданы: тёмная тема — через `html[dark]`.
- Окошко расширения (MV3) не выполняет код из строки: никаких `eval` и `new Function`,
  аргументы передаются через `executeScript({ args })`.
- Метатеги Instagram при переходах внутри сайта могут остаться от прошлого поста: сверять `og:url`.
- `applicationShouldTerminateAfterLastWindowClosed` — false: DownMax живёт в строке меню (`menubar.swift`).
  Закрыли окно — `setActivationPolicy(.accessory)`, значка в Доке нет; `showMainWindow()` возвращает `.regular`
  и перерисовывает плитку Дока. Значок строки меню обновляет `DockProgress` (тот же таймер). Строку меню
  перекрывает Sapphire пользователя — computer-use по значку щёлкнуть не может. Пока открыт любой модальный вопрос
  (NSAlert, окно «Компоненты»), `quit` через osascript возвращает «Отменено пользователем» (-128).

- aria2c: встроенный DNS (c-ares) на macOS не находит серверы. Свой aria2c собран без c-ares и флага `--async-dns`
  не знает (упадёт с «unrecognized option») — флаг ставится только Homebrew-версии (`Aria2.common`).
  Вывод разбирается по-английски — `LC_ALL=C`, иначе aria2c пишет по-русски.
- Для проверки торрентов: `https://webtorrent.io/torrents/sintel.torrent` (много файлов, качается
  через веб-сид; magnet у него не работает — нет участников) и торрент Debian netinst
  с `cdimage.debian.org/debian-cd/current/amd64/bt-cd/` (magnet за секунды, ~790 МБ — не докачивать).
